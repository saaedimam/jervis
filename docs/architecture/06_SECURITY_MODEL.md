# Security Model

## 1. Trust Boundaries
Jervis enforces strict security perimeters between its canonical layers. Trust flows downward from the system owner to untrusted external interfaces.

```
+-------------------------------------------------------------+
| UNTRUSTED EXTERNAL ZONE (CLI Inputs, REST API, MCP Clients) |
+-------------------------------------------------------------+
                              | (Submitted Action Request)
                              v
+-------------------------------------------------------------+
| TRUSTED RUNTIME SECURITY PERIMETER (Permissions & Event Bus)|
+-------------------------------------------------------------+
                              | (Authorized Execution)
                              v
+-------------------------------------------------------------+
| INTERNAL EXECUTION ZONE (Memory, Services, Storage)         |
+-------------------------------------------------------------+
                              | (Context Payload / Inference)
                              v
+-------------------------------------------------------------+
| EXTERNAL AI CONSUMER ZONE (OpenAI, Claude, Gemini, Ollama)  |
+-------------------------------------------------------------+
```

---

## 2. Permission Model
- **Capability-Based Authorization**: All service executions, filesystem operations, shell commands, and network requests require explicit capabilities.
- **Non-Bypassable Authorization**: The `Runtime Permissions` module (`internal/runtime/permissions`) intercepts every action request before it reaches the Event Bus or Service Layer.
- **User Prompting & Granular Policies**:
  - `Allow Always` (User explicitly pre-approved specific directory or command).
  - `Prompt User` (Runtime pauses execution and prompts interactive CLI/Desktop UI for authorization).
  - `Deny` (Action immediately aborted; security event logged to Timeline).

---

## 3. Plugin Isolation
- **No Direct Runtime Access**: Third-party plugins cannot access system memory or internal runtime state directly.
- **Sandboxed Execution**: Plugins execute inside an isolated WebAssembly (WASM) sandbox powered by `wazero` or via RPC isolation (`hashicorp/go-plugin`).
- **Capability Scoping**: Plugins must declare requested permissions in their manifest. The Runtime grants only user-approved capabilities.

---

## 4. Secret Management
- **Zero Plaintext Secrets**: API keys (OpenAI, Claude, Gemini) and OAuth tokens (Notion, Google Calendar) must NEVER be stored in plaintext configuration files or committed to code repositories.
- **OS Keychain Storage**: Secrets are stored in the host Operating System secure credential store (macOS Keychain, Linux Secret Service, Windows Credential Manager) via `github.com/zalando/go-keyring`.
- **In-Memory Sanitization**: Secret values in memory are wiped immediately after HTTP header authorization headers are constructed.

---

## 5. Filesystem Policy
- **Workspace Scoping**: File operations (read/write/delete) are restricted by default to the active project workspace root directory.
- **Path Traversal Protection**: All file paths are normalized and resolved via `filepath.Abs` and checked against allowed directory root prefixes to prevent `../` traversal attacks.
- **Protected System Paths**: The Runtime strictly denies access to system root (`/`), configuration directories (`/etc`), system binaries (`/usr/bin`), and SSH key stores (`~/.ssh`) unless explicitly granted with override flags.

---

## 6. Network Policy
- **Localhost Default**: Local APIs (REST daemon, MCP Server) listen strictly on `127.0.0.1`. Binding to public interfaces (`0.0.0.0`) is forbidden.
- **Explicit Outbound Egress**: Outbound HTTP requests are restricted to configured LLM Provider endpoints (OpenAI, Anthropic, Google, Ollama) and explicitly integrated services (Notion, Google Calendar).
- **Enforced Timeouts & TLS**: All HTTP client requests enforce TLS 1.3 encryption and hard timeouts (default 30s) to prevent resource exhaustion attacks.

---

## 7. Audit Logging
- **Immutable Timeline Ledger**: Every permission evaluation, CLI command invocation, tool execution, and AI request metadata (timestamp, action ID, requested capabilities, status) is recorded in the append-only Timeline store inside `internal/memory/timeline`.
- **Security Event Monitoring**: Denied permission attempts and path traversal violations trigger high-priority security log events emitted to the Observer module.

---

## 8. Threat Model & Mitigations

| Threat | Impact | Architectural Mitigation |
| :--- | :--- | :--- |
| **Prompt Injection Attack** | Malicious content in file/web page tricks LLM into requesting destructive shell execution. | AI output is untrusted. All tool calls generated by LLM pass through Runtime Permissions check prior to execution. |
| **Malicious Plugin Execution** | Third-party plugin attempts to read private SSH keys or exfiltrate local data. | Plugins execute inside isolated WASM sandbox (`wazero`) with zero filesystem/network access unless granted. |
| **API Key Exfiltration** | Malicious CLI flag or environment log dumps leak API keys. | API keys stored in OS Keychain; loggers automatically scrub authorization tokens from output. |
| **Unauthorized Remote Execution** | Remote attacker calls local REST daemon or MCP Server. | Local servers bind exclusively to `127.0.0.1` with mandatory local token authentication headers. |
